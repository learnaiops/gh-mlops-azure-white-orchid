# white-orchid

MLOps project on Azure: train, register, deploy, and monitor a health insurance risk prediction model using Azure ML, AKS, and Azure DevOps.
The domain is Insurance

## What this project does
Predict whether a customer is a "high risk" insurance customer based on health, lifestyle, and claims data.

## Data set

Synthetic health insurance risk dataset with features:
- age, BMI, smoker status, chronic conditions, annual income
- exercise frequency, alcohol usage, previous insurance claims
- family medical history, region

## Infra (Terraform)

### infra/ — pre-prod
- ML workspace, compute cluster, managed online endpoint
- App Insights + Log Analytics + ML workspace diagnostics
- App Service (Web App) for the UI with Key Vault references
- Key Vault holds: `ml-endpoint-key`, `prod-ml-endpoint-key`, App Insights secrets
- Variables: add `prod_ml_endpoint_url` after prod deploy to wire the UI

### infra-prod/ — prod
- `main.tf` — resource group (random suffix)
- `networking.tf` — VNet `10.2.0.0/16`, AKS subnet `10.2.0.0/22`
- `aks.tf` — AKS cluster (Standard_D4s_v3, autoscale 1–3) + `null_resource` AML extension install + compute attach
- `ml-workspace.tf` — Storage (GRS), Key Vault (purge-protected), ACR (Standard), Azure ML workspace
- `log-analytics.tf` — Log Analytics workspace, workspace-based App Insights, AKS diagnostics, ML workspace diagnostics, metric alerts (error rate >5%, latency >3s)
- `roles.tf` — AKS kubelet AcrPull, ML workspace ACR Contributor + AKS RBAC Admin + Storage Blob Contributor, SPN Data Scientist + Contributor + AKS User
- `monitoring.tf` — `null_resource` to enable model data collection (sampling_rate=1.0), `null_resource` to create `white-orchid-risk-prod-monitor` daily drift + prediction drift schedule; both skip gracefully if endpoint not yet deployed — re-run `terraform apply` after first pipeline run
- `dashboard.tf` — Azure Portal dashboard: endpoint requests/latency/failures, AKS CPU/memory/pods, App Insights exceptions, drift monitoring instructions
- `outputs.tf` — resource names for pipeline variable group + post-deploy instructions

## Model

- Algorithm: Gradient Boosting (sklearn) on health insurance risk dataset
- Model registered as `white-orchid-risk-model` in both workspaces
- Training data: `machinelearning/white-orchid/health_insurance_risk_dataset.csv`
- Quality gate: AUC ≥ 0.80 enforced in `train.py`

## UI (src/white-orchid-ui/)

React + Vite frontend, Node.js/Express backend (`server.js`).

- **Dual endpoint mode**: on form submit, calls `/api/predict` (pre-prod managed) and `/api/predict-prod` (prod AKS) in parallel using `Promise.allSettled`
- If both respond: shows side-by-side `ModelComparison` component — highlights when predictions differ (drift signal)
- If only pre-prod responds: shows single `RiskResult` (prod not yet deployed)
- Env vars required: `ML_ENDPOINT_URL`, `ML_ENDPOINT_KEY`, `PROD_ML_ENDPOINT_URL`, `PROD_ML_ENDPOINT_KEY`
- `PROD_ML_ENDPOINT_URL` and `PROD_ML_ENDPOINT_KEY` are set from Key Vault references in App Service once prod is deployed

## Monitoring (prod)

After `terraform apply` on `infra-prod/` **and** first `model-promote-prod-pipeline` run:

1. Re-run `terraform apply infra-prod/` to activate data collection and the `white-orchid-risk-prod-monitor` schedule
2. View the Azure Portal dashboard (URL in `terraform output dashboard_url`)
3. Drift reports appear in Azure ML Studio → Jobs → Monitoring

## Drift simulation

To simulate model drift, send scored data with shifted feature distributions (e.g., higher BMI/age cohort). The daily monitor will flag normalized Wasserstein distance > 0.1 (numerical) or Jensen-Shannon divergence > 0.1 (categorical).
